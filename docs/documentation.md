# Ama C component reference

This reference is generated by **Doxygen** from maintained C source/header
comments. Use its Files list and source browser to navigate compiler, runtime,
standard-library, native companion, tool and test components. The included
specification pages remain the language authority; generated reference pages
describe the implementation and do not replace those contracts.

From the repository root, install Doxygen and the pinned Python parser
(`python3 -m pip install -r docs/requirements-documentation.txt`), then run:

```sh
make docs
```

Open `docs/technical/index.html`. No compiler build is required. The generator
is selectable with `make docs DOXYGEN=/path/to/doxygen`; record `doxygen --version`
when collecting acceptance evidence. Configuration lives in `docs/Doxyfile`.
`make docs-clean` removes the generated folder and warning log; `make clean`
also removes them. Generated pages are not handwritten or versioned.

The generated folder includes `documentation-manifest.json`: the checked input
and Doxyfile fingerprints, coverage counts and exact Doxygen/Python/Markdown
parser versions. It matches `build/documentation/report.json` byte for byte.
Keep this manifest with the generated site when copying the folder.

The generator recursively includes maintained `.c` and `.h` files under `src/`,
`stdlib/modules/`, `tools/` and `tests/`. It excludes build trees and test
`generated/` outputs. Generated C is documented through its generators and verified
output contracts. Byte-exact malformed fixtures retain external purpose
explanations, as required by the contributor guide.

The build checks the reviewed per-file coverage registry, creates read-only
Doxygen input views and verifies actual canonical-rule destinations in HTML.
`make docs-reproducible` requires two complete generations to be byte-identical;
`make docs-complete` checks that every maintained input has reviewed documentation
and executable-consumer evidence, with no registered debt.
See `docs/implementation/documentation/README.md` for the exact
mapping, purpose/header/test checks, source navigation and remaining limits.

The baseline reference includes every retained file and extracted function/type.
Its XML gate rejects missing interface descriptions, and Doxygen warnings fail
the build; diagnostics remain visible in `build/documentation/warnings.log`.
Narrative guides are included with checked page identities. Temporary heading
compaction preserves their original parent tree and source line counts. Maintained
specification bytes remain unchanged.

The [current conformance report](implementation/conformance/release.md) connects
the implemented requirements to reviewed arguments and executable evidence.
Keep purpose and contract explanations beside code; let Doxygen generate all
reference pages and source views.
