# Private object construction phases

This is the T141 implementation argument, not a new language contract. File and
function reference pages are generated by Doxygen with `make docs`.
[LIFE-01](../../spec/implementation/native-interface.md#life-01) orders children
before the native payload; [LIFE-02](../../spec/implementation/native-interface.md#life-02)
selects one constructor; [LIFE-03](../../spec/implementation/native-interface.md#life-03)
requires cleanup of initialized resources. [RT-02](../../spec/implementation/runtime.md#rt-02)
requires stable instance storage. The broader [ownership contract](instance-ownership.md)
remains applicable. [Staged replacement](staged-replacement.md) composes this
construction boundary with final-identity reuse and destructive commit.

## Boundary and ownership

The sibling operations in `src/runtime/objects/construction/` receive an
operation-scoped runtime world/arena and the precise work record or cursor they
change. They do not receive compiler state. `create.c` owns the world guard,
protection lifetime and scratch arena; `build.c` drives the iterative traversal.

Reservation checks type/source/copy capability and reserves a private pool slot.
A work record becomes visible to cleanup only after that slot is registered in
the operation's work list. Failure before registration leaves the caller's work
pointer unchanged. Failure during subsequent field initialization returns the
registered record: its slot must still be released. A child records its parent
owner and its handle is installed into the parent's storage even when this late
initialization fails. The cursor follows that child so unwinding starts there.

Field preparation selects an explicit recipe or a declared default, invokes the
exact generated resolver when required, checks list counts/ledger overflow and
allocates handle storage. Earlier completed fields remain available to defaults.
Reference fields validate nominal type without constructing a target. Owned fields
extend the capacity ledger; they do not extend its initialized prefix yet.

Only after every owned child succeeds does the payload phase invoke the selected
default, literal or clone hook. A successful child advances its parent's live
prefix exactly once. A failed native constructor has no initialized-payload bit;
it is responsible for its own failed native acquisition and is never destroyed
as a successful payload. Clone reference fixups run before publication.

Publication changes private slots to public identities without moving payloads.
Source-linked copies retain their prepared service state, including explicitly
copied continuations. The operation guard excludes competing world operations;
publication is not a transaction for arbitrary concurrent readers. Valid completed
work is a precondition of the publication phase. Only successful creation changes
the public caller's output handle. All paths release scratch and source protections.

## Correctness and termination

The extraction preserves the former driver's tests, branch predicates and effect
order. Its loop invariant is: the cursor's ancestors own its reserved identity;
completed children form the exact initialized prefix; uncredited current children
are reached first by the failure cursor; no incomplete identity is public.
Reservation establishes ownership, descent preserves the ancestry relation and
successful ascent credits one completed child. Payload completion is permitted
only after all fields and children are complete. Thus induction over the finite
ownership tree establishes child-before-parent construction.

On failure, unwind reports the primary status once, cleans the cursor and then
its ancestors. Cleanup follows the initialized prefix in reverse ownership order,
continues after secondary errors and preserves the primary failure. A successful
but not yet credited child is cleaned from the cursor before the parent; a child
already credited is cleaned through the parent's ledger. It is never both.
Registered work pointers in scratch are not dereferenced as live payloads after
cleanup. The arena is reclaimed last.

For a finite descriptor/recipe tree, each field and child is advanced once; there
is no recursive C construction stack. Work storage is O(number of instances),
plus list handle buffers. The traversal's own phase dispatch is linear in fields
and instances; source protection, clone map/fixup lookup, allocator and native
hook costs are additional and are not claimed constant. Callback termination and
valid immutable descriptor/recipe lifetimes remain caller obligations. This
refactoring introduces neither a depth cutoff nor a guessed constructor.

## Executable evidence

The independent [construction cases](../../tests/unit/runtime/objects/construction/main.c)
use the real runtime world/pools and fault allocator. They distinguish failures
before/after reservation, inspect partial-child cleanup, preserve payload addresses
through publication, reject overflow/type mismatch before payload construction and
verify continuation/reference fixups. The [lifecycle cases](../../tests/unit/runtime/objects/lifecycle/main.c)
exercise every measured allocation prefix, each native constructor failure,
selected-constructor counts, nested/list cleanup and secondary cleanup failure.
