# Current boundary contracts and migration invariants

This T002 contract connects the [component map](../components.md) to the
[audit](../audit/README.md) and canonical requirements. It records how to
preserve or replace implementation boundaries. It does not define a different
language, freeze future C symbol spellings, or certify missing facilities.
File/interface reference pages are generated by Doxygen through `make docs`.

## Sources and complete identity

The source manager owns original bytes. Every borrowed span is half-open and
bounded by that source, and remains valid only while the manager owns the bytes.
Lexing and parsing return structured spans/nodes or an explicit diagnostic;
neither normalizes bytes nor changes literal payloads. TAB and exact lexical
validation precede activation/draft exclusion under
[SYN-01](../../../spec/language/source-and-names.md#syn-01) and
[SYN-04](../../../spec/language/source-and-names.md#syn-04).

Logical module identity is a root kind plus an ordered component sequence,
independent of its physical `name+/` location. Identity encoding must include
every part with explicit boundaries and a versioned category. For any two
supported identities, equality of encodings implies equality of their full
logical keys; a hash only selects a candidate. The registry compares original
keys and rejects unequal-key collisions under
[NAME-01/NAME-02](../../../spec/implementation/compiler.md#name-01).
Insertion either publishes one complete registry entry or leaves the previous
registry usable with an explicit failure.

Keep UTF-8 word recognition separate from complete-name/path composition.
Recognizing a word does not authorize trimming a name, joining adjacent words,
accepting repeated spaces, or guessing the root family. Complexity is linear in
the measured source/key length plus the chosen exact registry lookup cost.
Allocation and representability checks precede publication. Existing Unicode,
source-span, collision and catalog tests remain useful; new partitions include
multiword components, both root kinds, duplicate roots and lexical failures in
drafts. Planned consumers must preserve those identities through diagnostics,
native qualification and export naming.

## Binding and construction are separate passes

The parser owns source structure, never declaration lookup. The binder consumes
that structure and the resolved explicit declaration inventory. Apply
[TYPE-06](../../../spec/language/declarations.md#type-06) and
[NAME-06](../../../spec/language/declarations.md#name-06) before ordinary use
resolution; do not retrofit inference into C emission or the runtime.

For each scanned source prefix, maintain three distinct facts: module-variable
names encountered in that prefix, already typed inferred fields, and active
lexical foreach bindings. The encountered set excludes selector/label/path names
and local-resolved uses exactly as TYPE-06 specifies. Classification at one
receiver is a function of that prefix, not a successful later lookup. Explicit
later declarations retain ordinary visibility but cannot suppress an earlier
inferred declaration or repair an earlier unresolved-use classification.

Each inferred-field dependency on another inferred field leads to an earlier
declaration position. Following such edges strictly decreases a finite source
position, so inference has no inferred-field dependency cycle and terminates.
Explicit type resolution and initialization graphs are checked separately.
Foreach lookup reuses a compatible visible reference or creates exactly its
lexical local binding; runtime emptiness never changes classification.

Construction follows the declaration/initialization ordering contract rather
than control-flow reachability. Maintain separate graphs for module loading,
eager owned construction, constant initialization and clone capability under
[TYPE-04](../../../spec/language/declarations.md#type-04) and
[COMP-03](../../../spec/implementation/compiler.md#comp-03). A cycle in one graph
does not imply a cycle in another. Every graph operation has an explicit finite
vertex/edge domain; existing exact traversal/fixed-point arguments are retained
only when their edges still match the current contract.

Tests partition explicit/inferred/local names, before/after uses, duplicate
suffix forms, nested reuse, disjoint scopes, unavailable initializer sources,
eager cycles and benign recursive lists. Compile-time acceptance must not depend
on list contents, branch outcome or a convenient type name.

## Context ownership and checked admission

One execution context owns mutable pool descriptors, constant values and their
lifecycle ledgers, current-instance selection, failure/trace state and service
controls under [PAR-01](../../../spec/language/async-and-parallelism.md#par-01).
Immutable code, literal bytes and immutable descriptor templates may be shared;
mutable generated `AmaObjectType`/constant storage must be materialized per
context rather than shared through the old static registry.

A local handle is interpreted only inside its owning context. A wrapper that
selects among contexts carries and checks context identity before dereferencing
local storage; equal local triples in different contexts remain unrelated.
Identity history cannot wrap or revive old tokens. The compiled-library host
boundary later uses [EMBED-04](../../../spec/implementation/c-library.md#embed-04)'s
live identity records before accessing context/instance memory. This is distinct
from accepting an arbitrary C pointer as a safe handle.

At most one executor owns a context at a time. Admission refusal changes no
invocation/interface/continuation state; accepted technical failure makes that
context nonresumable. Independent contexts do not acquire a global current-host
lock. The admission mechanism must actually synchronize concurrent access when
threading is introduced, not rely on a racy Boolean. Transfer of executor
ownership requires the quiescent boundary in
[PAR-02](../../../spec/language/async-and-parallelism.md#par-02).

Core identity/admission tests belong in `tests/unit/runtime/context`; generated
isolation tests belong in `tests/integration/context/isolation`. Use equal local
numbers, wrong/stale context tokens, failed creation, reentry, yield, disposal
and identity exhaustion. Parallel acceptance additionally runs real independent
contexts concurrently. Merely allocating two host structs or rejecting the
second one is not isolation evidence.

## Stable ownership and replacement

Retain stable block pools, reserve/publish separation, initialized-prefix
ledgers and operation-scoped tree protection where their contracts are verified.
Reservation fixes final slot identity before initializers, while constructing
storage remains unavailable externally. Growth cannot move live payloads;
retirement and reclaim history cannot make an old handle live again under
[REF-04–REF-06](../../../spec/language/values-and-references.md#ref-04).

For copying, let `S` be the complete source ownership tree and `M` its prepared
source-to-destination map. `M` is total and injective over `S`. A stored reference
to `x` becomes `M(x)` exactly when `x` belongs to `S`; otherwise its checked
external identity is unchanged. Destination-root replacement maps the source
root to the existing destination identity. Native cloning does not invent an
additional Ama reference-fixup authority. The proof follows the ownership-tree
construction and later map-resolution pass, including forward/non-owning cycles,
under [COPY-04/COPY-05](../../../spec/language/values-and-references.md#copy-04).

Before commit, failures discard prepared resources and preserve previous live
state. Destructive commit starts only after validation/preparation succeeds;
destructor failure is terminal and cleanup continues without rollback or double
destruction under [COPY-02](../../../spec/language/values-and-references.md#copy-02).
T141/T142 separate construction/clone phases without altering that boundary.
Existing independent and parent lifecycle/clone/replacement tests are the
before/after witnesses; add a distinct test whenever an extracted meaningful
child operation has an independently checkable contract.

## Calls, control trees and suspension

Resolved IR must carry target/source/receiver locations, typed interface entries,
ordered actions, acquisition authorities, refusal targets and lexical loop roots.
No emitter infers those facts from C text or a field's spelling. T140 splits
emission by those resolved operations. T143/T144 separate source selection,
protection, preparation, transfer and cleanup with the exact order in
[CALL-08](../../../spec/language/calls-and-results.md#call-08).

Direct result operations act on selected declared result storage. Their service
frames and owner protections live through the complete descendant action subtree,
then release before the next sibling or local refusal handler under
[CALL-09](../../../spec/language/calls-and-results.md#call-09). They do not create
hidden caller fields or clone a method. A descendant refusal aborts only its
initiating operation tree, preserves prior effects and enters its own handler;
technical failure is not caught there.

Each condition loop has one lexical condition-entry label, body label and exit.
An inner backedge never restarts an enclosing call/branch/test. Detect empty
bodies before lowering: their full header is checked once, then execution exits
under [FLOW-02/FLOW-04](../../../spec/language/control-flow.md#flow-02).
Saved resume state includes active lexical control cells but never an acquired
grant or live C frame. Ordinary copying clears positions; continuation copying
preserves allowed saved state without caller links. Completion/restart/failure
cleanup must account for every active control slot.

Tests use repeated siblings, deep result chains, same-type nested calls, busy
aliases, every handler control exit, true/false/failing empty loops, nested repeat
roots and yield/resume inside bodies. Execute real generated C and check native
entry inlining; source-included pseudo-hosts cannot certify compiled-library
artifacts.

## List membership and live boundaries

Use [LIST-03](../../../spec/language/lists.md#list-03)'s order/record separation.
For each live order position `i`, the record selected by its membership identity
is live in the same collection incarnation and records position `i`. Removal
retires exactly that membership; slot reuse advances identity without wrap.
Target identity is distinct from membership identity, so duplicate reference
targets remain distinct entries. Local compact indices are valid only when
full checked identity can be reconstructed exactly.

Every active/suspended foreach cursor identifies its collection incarnation and
maintains `0 <= q <= n`. Selection advances q before checking its candidate;
committed insert/remove/clear correct every matching cursor by
[FLOW-05](../../../spec/language/lists.md#flow-05)'s exact formulas before output
actions run. Membership-origin checks prevent a loop binding from accessing a
removed entry even if its external referent remains live. Cursor registration,
restart, copying, scope exit and destruction must preserve the set of exactly
matching active/suspended slots; optimization is compared against a complete
lexical-slot scan, never a guessed subset.

Service acquisition protects the list/owner through its method/action tree.
Foreach selection releases it before user code. Each typed intrinsic method
validates only its own inputs and preflight effects, then either commits its
documented mutation/results or refuses before mutation/results. There is no
retained outcome flag or action enumeration. Length construction uses the exact
qualified integer bridge, not decimal formatting or payload casts.

Planned independent leaves `tests/unit/runtime/lists/membership`, `cursors` and
`methods` cover reduced-width exhaustion, duplicates, all q/position relations,
removed origins, nested/suspended registration, refused preparation and cleanup.
Parent generated-project tests compose mutation, selected-result actions and
continuation copying. Complexity names n, affected cursors and owned-tree work;
finite future insertion assumptions are explicit in traversal termination claims.

## External work and artifacts

The export model is validated before header/object emission. Host admission,
typed transport and owned snapshots follow
[EMBED-01–EMBED-06](../../../spec/implementation/c-library.md#embed-01); no borrowed
Ama address/handle becomes a portable C result. Native foreign-component resources
use the explicit exception in EMBED-07/EMBED-08. A child C call must return before
the outer adapter yields, and neither adapter reenters an active ancestor.

Native callbacks own native buffers/tokens only. Completion is published by the
owning executor after matching the complete live registration/run identity under
[ASYNC-05/ASYNC-06](../../../spec/language/async-and-parallelism.md#async-05).
Independent contexts exchange bounded typed messages, not local handle triples.
The scheduler's finite round budgets count completed steps/imports; they cannot
preempt a nonreturning step or make an open live foreach a bounded round.

Relocation uses a complete injective identity mapping and rewrites only resolved
path spans under [TOOL-02](../../../spec/implementation/tools-and-conformance.md#tool-02).
Staging revalidates the complete reference graph before publication; failure
preserves originals or retains explicit recovery state. Keep it distinct from
native scaffold publication: reusable filesystem primitives do not make their
different transaction domains interchangeable. T139's publication split retains
descriptor/path ownership and rollback invariants for its own finite artifact set.

Every planned boundary has independent and real-parent test homes in the
component map. Before its task completes, record the actual commands, failure
partitions, correctness/complexity argument and current implementation limits in
the registry. Generated reference output is evidence of documentation generation,
not evidence that these new facilities already exist.
