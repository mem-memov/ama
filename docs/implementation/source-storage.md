# Source storage

Implementation evidence for the subset recorded in the [T001 audit](audit/README.md).
The [specification](../../spec/README.md) defines current behavior; this
component description does not certify the open work in [TODO](../../TODO.md).

Boundary: `src/source/text/source.h`, `text/` and `io/`. Implements SRC-01,
SRC-03 byte preservation and NAME-03 source coordinates, not tokenization.

A manager owns separately allocated immutable source records, path copies, bytes
and line tables. A span is a borrowed record pointer and half-open byte offsets;
all survive additions and expire on manager destruction. Input views need only
survive the add call. Allocator callbacks must have malloc/free semantics,
including accepting NULL on release, and remain usable for the manager lifetime.
The extra zero byte is convenience storage, never part of the source length.
Embedded NULs remain data; later lexical validation decides their admissibility.

Allocation, size and I/O failures publish nothing and preserve the output value.
The file reader closes its stream on every path, preserves an earlier failure,
and releases temporary storage. Concurrent modification of an input file is an
external I/O condition: the source is precisely the bytes successfully read,
not a promised filesystem snapshot. Loading itself does not validate UTF-8.

Construction allocates a zero-initialized private record, then path, bytes and
line table. Each failure releases this private ownership set. Only success links
the complete record. Induction over additions proves that existing records and
views never move. Destruction removes one record per iteration and releases its
four allocations. Checked arithmetic rejects unrepresentable storage sizes.

Line starts are 0 and the offsets immediately after LF, strictly increasing.
Binary search maintains the interval containing the greatest start <= offset.
The interval decreases until its lower endpoint is that predecessor; line and
byte column are respectively its index + 1 and offset - start + 1. EOF is valid,
including the empty final line after LF. Excerpts exclude LF and its preceding
CR; a bare CR remains source data. Columns count bytes, not terminal cells.

Adding n bytes and p path bytes costs O(n+p) time and storage; locating one offset
costs O(log l) for l lines. Geometric read buffers cost O(n) total copying and
storage. Record teardown costs O(number of sources). Manager operations require
exclusive access; there is no shared mutable compiler singleton.

Evidence: `make -C tests/unit/source/text` passed with C11, pedantic and Werror.
Tests preserve Unicode/NUL/CRLF bytes across 100 additions, compare every offset
against a linear line model, inject every allocation failure for add/load, and
exercise missing files. This component itself owns source storage, not a compiler project.


T145 adds declaration-level ownership/failure comments and canonical rule links
throughout the retained source foundation. The independent
[arena cases](../../tests/unit/source/memory/main.c) verify max-alignment, stable
addresses including zero-size requests, checked size failure before allocation,
failed joins preserving earlier strings, bulk cleanup and the stateless system

## T014: exact EOF, checked growth and failure publication

The manager rejects length SIZE_MAX before allocation or input-byte access:
its convenience terminator requires one representable additional byte. Source
length remains the original n, not n+1. This check does not depend on allocator
availability. A zero-length source still owns a convenience terminator and has
EOF at line 1, byte column 1. A file without final LF ends on its existing line;
no virtual lexical boundary appends a physical byte or source line. A real final
LF introduces its genuine following empty position. Columns include every UTF-8
byte; neither scalar counting nor display width changes these offsets.

`src/source/io/buffer/` separates numeric planning from byte allocation/commit.
`source_buffer_plan` accepts the current length/capacity and exact addition,
checks `length <= capacity < SIZE_MAX`, and proves the sum at most SIZE_MAX-1
before adding. It preserves sufficient capacity; otherwise it doubles the
required count and saturates once at SIZE_MAX-1. The previous exact-capacity
near-limit tail could reallocate on each subsequent chunk, contradicting a
full-domain linear-copy argument. One final saturation removes that tail.
Planning changes its output only on success and allocates nothing; its numeric
boundary tests need no enormous actual array.

`source_buffer_append` allocates replacement storage before changing ownership.
It copies the existing prefix and appended bytes before releasing old storage.
Thus a chunk borrowed from the buffer itself remains valid across growth;
memmove also handles overlap when no growth is required. Allocation failure
leaves the old pointer, capacity, length and all old bytes intact. Empty append
allocates nothing. The binary loader owns this temporary buffer until read/close
and final immutable publication have completed, on either success or failure.
Its maintained test manifests explicitly include both buffer implementation files.

Each nonsaturated growth at least doubles the previous capacity; the sum of
copied old prefixes is bounded by a geometric series. There is at most one final
saturated copy, whose old prefix is at most the final length. Appended chunks
are copied once each, so total buffer copying is O(n), with O(n) private storage.
No allocation retry, guessed size cutoff or fallback representation is needed.
For the line index, accepted source length is at most SIZE_MAX-1, so counting
one plus the number of actual LF bytes cannot overflow. Its separate checked
array-size multiplication bounds storage before allocation. Binary predecessor
search and one-based byte columns then remain representable, including EOF.

The source/text leaf now checks 55,987 original-byte inputs: every sequence up to
length six over text, CR, LF, NUL and two UTF-8 bytes. Every offset through EOF is
compared with a direct physical-byte model, independently of the stored line
index. This is a bounded code check; the index/search invariants above cover
arbitrary representable sources. Deliberately malformed UTF-8 byte sequences
remain storage fixtures: strict language decoding belongs to T015.

Other cases mutate borrowed path/data after add, verify unchanged failure outputs
and exact Unicode byte columns, exercise all planner size endpoints, and append
internal prefixes before/after growth with injected allocation failure. Real
loads cover empty files, optional final newline, CRLF, a multibyte scalar crossing
a read boundary and multiple growth allocations. Every measured load allocation
is failed while a previous published source remains unchanged; all partial
allocations are released. Missing-file and actual directory-read failures preserve
that earlier source. Existing integration cases retain original diagnostics and
compile/run real C `#line` mappings with Unicode and escaped physical paths.

T014 acceptance passes the full strict `-DNDEBUG -Werror` tree and focused
source/diagnostic ASan/UBSan leaves (leak detection disabled). Complete coverage
checks 763 maintained inputs with zero debt. Warning-free Doxygen checks 591
maintained files, 2432 interfaces and all 288 canonical/page destinations;
two complete generations produce byte-identical output. Markdown links resolve.
