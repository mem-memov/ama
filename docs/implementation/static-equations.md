## Recovery invariant

Let the independently known result be R = (D, B, S): original ordinary definition
D, complete fixed map B and residual set S. Let P be the explicit named input
set of the application. Every P member must be an original D formal, distinct,
and fixed in R. Thus P is a subset of dom(B), disjoint from S.
The sole possible preceding constructor is (D, B minus P, S union P).
Forward application must reconstruct R and equate each supplied value with its
corresponding B value. Additional residuals and unused captures survive exactly.
No separately supplied expected signature chooses a partition or an origin.
When the result has no independently known nominal origin, the obligation stays
pending. A bare forwarding expression in a partial context imposes equality.

## Progress, bounds and ownership

Request admission rejects unnamed or omitted static requests before counters,
links or allocations change; ordinary runtime positional/skip handling remains.
Each known application validates original residual membership, then forms the
disjoint union of retained captures and supplied named values. Direct and staged
union are associative and source-order independent; omitted formals remain bound
residuals, not inference holes. Field inference is a separate ordinary policy.

Recovery checks P against D and the fixed domain of B, never the filesystem or
a set of possible origins. It allocates at most B capture entries, with checked
size multiplication, and copies only entries outside P. For D original formals,
B fixed entries and P supplied names, validation/filtering takes
O(P(D + B)) time and O(B) owned capture storage. Existing nominal interning and
finite equation solving retain their own bounds. No source definition is unfolded
and no recursive source/body/type walk is introduced. A missing nominal origin
remains pending. A producer/selector is refused before any recovery equation is
created, since arbitrary graph outputs do not provide nominal injectivity.

All partial records stay with their existing arenas on failure; caller outputs
and prior published application snapshots are unchanged. Immutable source, actual
maps and term payloads are never rewritten by solving. Repeated snapshots alone
are not progress: later orchestration must reschedule only for new structural
facts. T209 establishes finite individual operations, not a definition-expansion
termination claim or whole-program executable admission.

Strict flags are `-O0 -g -Wall -Wextra -Werror -std=c11 -pedantic
-D_POSIX_C_SOURCE=200809L`, supplied through `C_COMPILER_FLAGS`. Sanitized runs use
O1, `-fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie`,
`LINKER_FLAGS=-fsanitize=address,undefined -no-pie`,
`ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` and `UBSAN_OPTIONS=halt_on_error=1`.
Leak instrumentation retains the established container restriction; counted
teardown independently proves fixture ownership, including every swept refusal.
